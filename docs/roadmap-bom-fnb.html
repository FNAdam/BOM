Bill of Materials untuk Produk Minuman

Satu sumber kebenaran yang merangkai resep multi-level, biaya standar, COGS aktual, sampai penetapan harga jual — supaya angka resep, pabrik, dan finance akhirnya bicara dalam bahasa yang sama.

Stack: ASP.NET Core · React · PostgreSQL Core BOM · Costing · COGS · Pricing Mata uang IDR 8 Fase eksekusi
01

Kenapa dibangun

Di banyak produsen F&B, resep dan biaya masih tersebar di spreadsheet. Struktur bertingkat sulit ditelusuri, konversi satuan rawan salah, dan biaya tidak pernah benar-benar terbukti.

Masalah hari ini

  • Resep multi-level (base/syrup → produk jadi) sulit ditelusuri antar file.
  • Konversi satuan kg↔g, L↔ml manual dan rawan salah hitung.
  • Biaya standar tak akurat — susut (scrap & yield) tidak diperhitungkan.
  • COGS aktual tak bisa dibandingkan dengan standar → selisih tak ketahuan.
  • Harga jual ditebak, tanpa dasar margin, PPN, dan jenjang channel.

Yang ingin dicapai

  • Master item & BOM multi-level dengan versioning yang auditable.
  • Cost roll-up biaya standar otomatis, termasuk scrap & yield.
  • Procurement/MRP sederhana: dari rencana produksi ke saran pembelian.
  • COGS aktual per batch + analisa variance (price/usage/yield).
  • Harga jual dari COGS: margin/markup, PPN, channel, break-even.

04

Bahasa domain

Beberapa istilah yang paling sering tertukar — dan justru menentukan benar-salahnya angka.

Scrap % komponen
Susut/kelebihan bahan per komponen (mis. tumpahan sirup 1%) — menambah kebutuhan input.
Yield % BOM
Rendemen output keseluruhan (98% → 2% batch hilang) — menaikkan biaya per unit baik.
Semi-finished / Base
Produk antara (base kopi, syrup) yang punya BOM sendiri → memicu struktur multi-level.
Cost roll-up
Perhitungan biaya standar produk secara rekursif dari seluruh komponennya.
COGS
Biaya aktual barang diproduksi/dijual = material + konversi (labor + overhead).
Markup vs Margin
Markup: laba atas cost (Price = Cost×(1+m)). Margin: laba atas harga (Price = Cost/(1−m)).
Contribution margin
Harga jual − biaya variabel (proksi COGS); jadi dasar analisa break-even.
Channel & HET
Jenjang harga ex-factory → distributor → retail → HET (harga eceran tertinggi), tiap jenjang punya margin (bisa disetel).
Pack level / Selling UoM
Hierarki kemasan jual: Botol (base) → Pack (isi 12) → Karton (isi 24). Harga level = harga botol × isi. Harga ada di produk jadi, bukan di botol PET (itu bahan/COGS).
PPN
Pajak 11%/12%. Harga B2B disimpan tax-exclusive; HET ke konsumen sudah termasuk PPN.

06

Algoritma inti

Tiga mesin hitung: roll-up biaya standar (rekursif), COGS aktual dari konsumsi, dan penyebaran harga jual per channel.

Cost roll-up (rekursif)

+ cycle detection
StandardCost(item, visited):
  # tolak referensi melingkar
  if item in visited: throw CircularBom
  bom = ActiveBom(item)
  if bom == null:            # item dibeli / raw
    return HargaSupplierPreferred(item)
  material = 0
  for c in bom.Components:
    qty = ConvertUom(c.Qty, c.Uom, base)
    qty = qty * (1 + c.ScrapPercent)
    material += qty * StandardCost(c.Item, visited+item)
  material /= bom.OutputQuantity   # per 1 unit
  material /= bom.YieldPercent     # koreksi rendemen
  return material + KonversiPerUnit(bom)

COGS aktual

saat order ditutup
matCost  = Σ (konsumsi.QtyAktual × BiayaAktual)
convCost = labor + overhead aktual
COGS_total = matCost + convCost
COGS_unit  = COGS_total / order.QtyAktual

# terima ke inventory (moving average)
ProdReceipt(item, qty, unitCost = COGS_unit)

# variance vs standar
Price = (HargaAktual − HargaStd) × QtyAktual
Usage = (QtyAktual − QtyStd)   × HargaStd
Yield = (OutputStd − OutputAktual) × CostUnitStd

Harga jual (pricing)

margin editable · per level
cost   = Standar atau LastCOGS
target = Setting.margin      # bisa diubah
base   = margin ? cost/(1−target)
       : markup ? cost*(1+target)
if base < FloorCost: tolak     # BR-8
perBotol = base
for ch in Channels:
  perBotol *= (1 + ch.Margin)    # margin editable
  for lvl in PackLevels:   # botol/pack/karton
    harga = perBotol * lvl.Isi
    HET   = harga + PPN
break-even = FixedCost / (netBotol − cost)

09

Business rules kunci

BR-1

Hanya satu versi Active per produk pada satu waktu — tanggal efektif tak boleh overlap.

BR-2

Cycle detection — BOM tak boleh mereferensikan dirinya langsung/tak langsung.

BR-3

UoM baris komponen harus convertible ke base UoM item (dimensi sama, atau density terdefinisi).

BR-4

Scrap % ≥ 0; Yield % dalam rentang (0, 1].

BR-5

Mengubah BOM Active membuat versi baru (immutable/auditable), bukan edit di tempat.

BR-6

Roll-up disimpan sebagai snapshot bertanggal; wajib recompute saat biaya/struktur berubah.

BR-7

COGS memakai konsumsi aktual; variance ditandai bila melebihi toleransi.

BR-8

Harga jual tak boleh di bawah floor; margin < target minimum ditolak/ditandai.

BR-9

Price list bertanggal & tak overlap per (produk, channel); ubah harga aktif → versi baru.

Cara menjalankan (Fase 1)

Setup lokal untuk hasil Fase 1. Jalankan berurutan dari root project. Migration InitialCreate sudah dibuat — tinggal di-apply ke database.

Prasyarat: .NET 10 SDK Node 20+ WSL2 + Docker Engine (Ubuntu)

📁 Dua terminal. Langkah 1 (Docker/Postgres) di terminal Ubuntu (WSL2) pada path /mnt/d/FNA/.../BOM. Langkah 2–4 (.NET & frontend) di PowerShell Windows pada D:\FNA\...\BOM (langkah 4 pindah ke subfolder web). Keduanya menunjuk folder project yang sama — WSL2 mem-forward port 5432 ke Windows sehingga koneksi tetap localhost (appsettings tak perlu diubah).

  1. 1

    Nyalakan database (PostgreSQL via Docker di WSL2)

    di: terminal Ubuntu (WSL)

    Docker Engine ada di dalam Ubuntu (WSL2), jadi langkah ini dijalankan di terminal Ubuntu — bukan PowerShell. Postgres 17, db/user/pass = bom / bom / bompass, port 5432.

    1. Buka Ubuntu (WSL). Dari PowerShell ketik wsl, atau buka app "Ubuntu" dari Start Menu.
    2. Nyalakan Docker daemon di dalam WSL (kalau belum jalan): 
      sudo service docker start
    3. Masuk ke folder project — drive D: Windows di-mount di /mnt/d: 
      cd "/mnt/d/FNA/Work/01. Documents/Absen/Adam/Latihan/BOM"
    4. Nyalakan container Postgres (mode background): 
      docker compose up -d

      Kalau muncul "permission denied", pakai sudo docker compose up -d (atau tambahkan user ke grup docker).

    5. Cek sudah jalan — harus muncul container status Up: 
      docker ps

    Port 5432 otomatis terforward ke Windows (WSL2), jadi app .NET di Windows konek via Host=localhost;Port=5432. Hentikan DB: docker compose down · log: docker compose logs -f · data aman di named volume.

    dotnet run --project src/Bom.Api
  4. 4

Contoh query

Daftar item + satuan + kategori

SELECT i.code, i.name, i.type, u.code AS uom,
       c.name AS kategori, i.standard_material_cost
FROM items i
JOIN uoms u ON u.id = i.base_uom_id
LEFT JOIN item_categories c ON c.id = i.category_id
ORDER BY i.code;

Resep (BOM) + komponen suatu produk

SELECT b.version, b.status, b.output_quantity,
       ci.code AS komponen, bc.quantity,
       cu.code AS satuan, bc.scrap_percent
FROM boms b
JOIN bom_components bc ON bc.bom_id = b.id
JOIN items ci ON ci.id = bc.component_item_id
JOIN uoms cu ON cu.id = bc.uom_id
WHERE b.product_item_id =
      (SELECT id FROM items WHERE code = 'FG-0001')
ORDER BY bc.sequence;

Saldo stok & harga rata-rata

SELECT i.code, i.name, b.qty_on_hand, b.average_cost
FROM inventory_balances b
JOIN items i ON i.id = b.item_id
ORDER BY i.code;

Harga jual aktif per level & channel

SELECT i.code, ll.tier_name, pk.name AS pack,
       ll.net_price, ll.gross_price
FROM price_lists pl
JOIN items i ON i.id = pl.product_item_id
JOIN price_list_lines ll ON ll.price_list_id = pl.id
JOIN pack_levels pk ON pk.id = ll.pack_level_id
WHERE pl.status = 'Active'
ORDER BY i.code, ll.id;

Nama tabel/kolom memakai snake_case; nilai enum disimpan sebagai teks (mis. status = 'Active', type = 'FinishedGood'). Tabel __EFMigrationsHistory = riwayat migrasi EF — jangan diubah manual. Ganti password default bompass sebelum dipakai di lingkungan nyata.

    di: supabase.com

    URI yang tersalin itu terlihat rumit, tapi sebenarnya cuma 3 potongan info yang digabung jadi 1 baris. Contoh konkret (angka/huruf punya Anda pasti beda — ini cuma ilustrasi):

    postgresql://postgres.abcdxyzklmn:[YOUR-PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres

    Tabel ini artinya: lihat warnanya di URI Anda (baris di atas) → ambil tulisannya persis seperti kolom tengah → tempel jadi nilai di kolom kanan (ini nama field di template Npgsql, bukan di Supabase):

    WarnaYang Anda ambil dari URI AndaJadi nilai field
    hijausemua tulisan antara @ dan :5432 — salin utuh, jangan dipotongHost=...
    oranyesemua tulisan antara :// dan tanda : sebelum password (selalu diawali postgres.) — salin utuhUsername=...
    merahbukan disalin — tulisan [YOUR-PASSWORD] diganti dengan password database yang Anda simpan di langkah c tadiPassword=...

    Hasil jadinya — 3 warna yang sama, sudah dipindah ke template lengkap (bagian putih/tak berwarna — Port, Database, SSL Mode — biarkan persis seperti ini, jangan diubah):

    Host=aws-0-ap-southeast-1.pooler.supabase.com;Port=5432;Database=postgres;Username=postgres.abcdxyzklmn;Password=password-anda-di-sini;SSL Mode=Require;Trust Server Certificate=true

    Warna di sini cuma penanda visual biar gampang mencocokkan — tampilan asli di URI Supabase / terminal Anda tidak berwarna seperti ini.

    Simpan hasil di atas (connection string lengkap, sudah diganti) — dipakai 2 kali: sekali untuk apply migration di bawah ini, sekali lagi untuk Environment Variable di Render (langkah 3). Apply skema (migration) ke Supabase dari komputer Anda, cukup sekali:

    $env:ConnectionStrings__Default = "Host=aws-0-....;SSL Mode=Require;..."
dotnet ef database update --project src/Bom.Infrastructure --startup-project src/Bom.Api

    Berhasil kalau output terakhir Done. tanpa error. Cek: Supabase dashboard → menu kiri Table Editor → harus muncul daftar tabel (items, boms, uoms, dst).

    2. Halaman berikutnya minta sumber kode: pilih Build and deploy from a Git repository → klik Next.

    FieldIsi

Kalau tidak diisi, aplikasi pakai nilai default yang ada di kode sumber (publik di GitHub) — siapa pun yang baca kode bisa memalsukan token login tanpa tahu password. Generate nilai acak sendiri, contoh lewat PowerShell: [Convert]::ToBase64String((1..32|%{Get-Random -Max 256})) — salin hasilnya, tempel sebagai value, jangan dipakai ulang dari contoh di panduan ini.

    Plan B — Self-host + Cloudflare Tunnel

    1. Install cloudflared sekali saja:
    winget install Cloudflare.cloudflared
    1. Jalankan backend lokal, tapi arahkan ke database Supabase (bukan Postgres lokal) supaya datanya sama dengan yang dipakai GitHub Pages nanti — di PowerShell, folder root project:
    $env:ConnectionStrings__Default = "Host=aws-0-ap-northeast-1.pooler.supabase.com;Port=5432;Database=postgres;Username=postgres.blfmfikusvlszhqtmkce;Password=PASSWORD_ANDA;SSL Mode=Require;Trust Server Certificate=true"
$env:Cors__AllowedOrigins__0 = "https://fnadam.github.io"
dotnet run --project src/Bom.Api

    Biarkan jendela PowerShell ini tetap terbuka & jalan. Catat juga port yang dipakai (biasanya muncul di log, mis. http://localhost:5099).

    Dijalankan begini, login tetap pakai kunci penanda token bawaan dari kode (bukan yang acak di Render/Back4App) — tidak masalah untuk tunnel sementara di komputer sendiri, tapi kalau mau lebih aman tambahkan juga $env:Jwt__Key = "(string acak 32+ karakter)" sebelum baris dotnet run di atas.

    1. Buka jendela PowerShell baru (yang lama jangan ditutup) → jalankan:
    cloudflared tunnel --url http://localhost:5099

    Akan muncul baris seperti https://kata-acak-1234.trycloudflare.com — itu URL publik backend Anda. Berlaku selama jendela PowerShell ini tetap terbuka (tidak perlu login/daftar akun Cloudflare sama sekali untuk cara ini). Pakai URL ini untuk langkah 4, menggantikan URL Render.

    URL berubah tiap kali tunnel di-restart (tutup lalu buka ulang jendela ke-2) — kalau itu terjadi, Anda harus update ulang secret VITE_API_URL di langkah 4 dan jalankan ulang workflow-nya. Troubleshooting — error yang paling sering muncul

"Failed to fetch" / CORS error di Console (F12) — nilai Cors__AllowedOrigins__0 di Render tidak persis sama dengan URL GitHub Pages (perhatikan https://, tanpa garis miring / di akhir, tanpa /<repo>). Perbaiki di Render → tab Environment → edit value → Save Changes (otomatis redeploy).

Halaman GitHub Pages putih kosong — biasanya workflow belum selesai jalan, atau secret VITE_API_URL ditambahkan setelah workflow terakhir jalan. Jalankan ulang: tab Actions → workflow → Run workflow.

Render build gagal, error "file not found" / "no such file or directory" — hampir selalu karena Root Directory terisi (harus kosong) atau Dockerfile Path salah ketik. Perbaiki di service → Settings → Build & Deploy → edit field tsb → Save Changes (akan redeploy otomatis). Lihat tabel field & alasannya di langkah 3.

Data gagal simpan, error soal tabel/"relation does not exist" — migration belum di-apply ke Supabase. Ulangi perintah dotnet ef database update di langkah 2 dengan connection string Supabase yang benar. Ini juga berlaku kalau baru pertama kali pull kode dengan fitur login (ada tabel baru app_users) — jalankan ulang perintah yang sama, migration baru akan ikut ter-apply.

Halaman login muncul terus walau password sudah benar / "401 Unauthorized" — cek: (1) migration terbaru sudah di-apply ke Supabase (lihat pitfall di atas, perlu tabel app_users); (2) username persis admin huruf kecil semua; (3) kalau sudah pernah ganti password, pakai password yang baru bukan ChangeMe123! lagi.

Error di log "(ENOIDENTIFIER) no tenant identifier provided" — Username di connection string cuma postgres (tanpa akhiran project-ref). Pooler Supabase melayani banyak project lewat satu host, jadi wajib Username=postgres.<project-ref> (titik + kode project, contoh postgres.blfmfikusvlszhqtmkce) supaya dia tahu mau connect ke project yang mana.

Error di log "Failed to connect to [xxxx:xxxx:...]:5432" / "Cannot assign requested address" — alamat di dalam kurung siku itu IPv6, artinya connection string Anda memakai host Direct connection (db.<project-ref>.supabase.co), bukan host pooler. Host Direct connection Supabase cuma IPv6, dan kebanyakan platform hosting gratis (Render/Back4App) tidak punya akses keluar IPv6 → gagal connect. Perbaiki Host di connection string jadi host pooler (aws-0-<region>.pooler.supabase.com, yang IPv4) — lihat langkah 2 untuk cara mengambilnya, dan jangan lupa Username tetap pakai format postgres.<project-ref> seperti pitfall di atas.

Render sangat lambat saat pertama dibuka — bukan error, tier gratis Render tidur setelah 15 menit idle dan butuh ±30-60 detik untuk bangun lagi.

(Plan B 3C) Tiba-tiba tidak bisa diakses dari GitHub Pages — tunnel Cloudflare mati karena jendela PowerShell-nya tertutup, komputer sleep/restart, atau koneksi internet putus. Buka lagi kedua jendela PowerShell (backend + cloudflared), URL baru akan terbit → update lagi secret VITE_API_URL di langkah 4.

(Plan B 3B) Error "No Dockerfile in this folder" — Root Directory yang diisi tidak punya file bernama persis Dockerfile di dalamnya (mis. diisi src/Bom.Api, yang isinya kode saja). Perbaiki: kosongkan Root Directory (atau isi .) supaya Back4App memakai Dockerfile di folder root repo yang sudah disiapkan untuk ini.

(Plan B 3B) "Deploy failed!" — "Either dockerfile must expose tcp port or define port in settings" — beda dari Render, Back4App butuh port dideklarasikan statis (lewat baris EXPOSE di Dockerfile), bukan cuma lewat variabel $PORT saat runtime. Dockerfile project ini sudah diperbaiki untuk punya EXPOSE 8080 — pastikan Anda sudah git pull versi terbaru lalu push ulang / biarkan Back4App redeploy otomatis dari commit terbaru di GitHub.

(Plan B 3B) Back4App container sering restart sendiri — kemungkinan kehabisan RAM (jatah 256 MB). Cek tab Logs di dashboard Back4App untuk pesan "out of memory"; kalau iya, pertimbangkan Plan B 3C atau tetap coba Render dulu.

(Plan B 3B) Error "Substitution variables must begin with an underscore or uppercase letter..." saat isi Environment Variable — nama variabelnya mengandung huruf kecil (Back4App mewajibkan huruf besar semua). Tulis CONNECTIONSTRINGS__DEFAULT dan CORS__ALLOWEDORIGINS__0 (semua huruf besar, garis bawah ganda tetap) — ASP.NET Core tetap baca ini dengan benar karena case-insensitive.
